## 二、作为作品，亮点在哪

结论：**卖点不是"做了个电商 agent"，是"能在别人看不出问题的地方看出问题，并且能证明自己修对了"。**

### 第一梯队

| 亮点 | 为什么值钱 |
|---|---|
| **手写 Agent Loop，不用 LangChain** | 大多数同类项目证明的是"会看框架文档"。手写循环 + 中间件管道 + 事件总线，证明的是**懂 agent 是怎么跑起来的** |
| **流式感知脱敏 + 滞后窗口 + 尾部优化** | 跨块匹配要压住输出，压住输出就毁了流式（22ms→297ms）。识破"敏感模式字符集是闭合的"→撞到汉字立即放行→**297ms 回到 24ms**。有问题、有取舍、有实测数字 |
| **`riskLevel !== 'high'` 才重试** | 一行代码，推理链完整：超时最可能是**响应丢了而请求已在下游执行完**，重试 = 第二次退款 |
| **三维回归门（质量/成本/延迟）** | 每次改动自动比对基线，任一维退化就红。是平台思维不是功能思维 |

### 第二梯队

- **EventBus 的复用证据** —— v0.6 SSE、v0.10 安全事件、v0.14 指标三次接入，`AgentLoop` 一行没改。
  抽象好不好不看设计文档，看**后来加东西时改了几个文件**。
- **`ToolGateway` 接口化** —— 识别出 `tool.execute` 是函数引用、跨不了进程，拆服务不是性能问题是**架构死结**。
- **Artifact 协议** —— 工具产出的结构化数据不经过模型直接给调用方。
- **15 版全程留档 + tag** —— SPEC/PLAN/REPORT 三件套 41 份。

### 最独特的一条：那张 bug 清单

```
v0.2  能力写了但没接进管道，测试全绿运行时零引用
v0.11 maxTokensPerSession 限的不是 session，同会话 300k 一次不拦
v0.12 退款执行不了，且失败信息谎称"用户取消"，模型据此回客户"已处理"
v0.14 ResponseScorer 越啰嗦分越高，且十三个版本没人读过它
```

**共同点是单元测试全绿、端到端行为是错的。**

## 三、离"企业级"还差什么（差距清单）

按**不补就出事的顺序**排。这不是功能清单，是风险清单。

### 🔴 P0 —— 现在这样上线，第一天就出事 → **已立项 [v1.1](iterations/v1.1-tenancy/SPEC.md)**

| 缺口 | 具体是什么 | 后果 |
|---|---|---|
| **完全没有认证鉴权** | `app.ts` 里没有任何 `onRequest`/`preHandler`，没有 API Key、没有 JWT | 端点裸奔 |
| **`tenant_id` 是客户端自己声明的** | 请求体里传什么就是什么（`app.ts:241`）——租户配置、配额、账本全挂在这个值上 | **改一个字段就能烧别人的额度、读别人的会话、改别人的安全规则。最严重的一条** |
| **没有限流** | ROADMAP 写了令牌桶，实际没实现 | 一个死循环客户端就能打爆 |
| **没有幂等键** | 对外 API 层没有 `Idempotency-Key` | 客户端重试 = 重复退款。内部工具做了防重放，**入口没做等于没做** |

这四条是一组的，本质是同一件事：**没有把"调用方是谁"这个概念建进系统**。

### 🟡 P1 —— 撑不住规模或说不清账

| 缺口 | 说明 | 归属 |
|---|---|---|
| 没有真正的分布式追踪 | 有 `traceId` 透传和 Prometheus 指标，但**没有 span 上报**。拆服务后"慢在哪一段"答不上来 | v1.2 |
| 配额"先检查后扣减"有超发 | 上限 = 并发数 × 单轮用量。已知可测，但企业对账时超发就是白送 | v1.2 |
| 会话无并发控制 | 同一 session 两个请求并发写入会互相覆盖 | v1.2 |
| 单点模型 provider | 无 fallback、无多 provider。熔断只保证不拖死自己，**没保证还能服务** | v1.2 |
| Prompt 没有版本管理 | 硬编码在代码里。**改 prompt 是最频繁的变更，却是唯一要发版的变更** | v1.3 |
| 答案质量零评测 | 评测集只覆盖编排层。需要 LLM-as-judge + 人工标注集 | v1.3 |

### 🟢 P2 —— 合规与运维

- **数据合规**：PII 明文落 PG，日志未脱敏，无保留期与删除接口
- **告警与 SLO**：有 `/metrics` 但无告警规则、无 dashboard、无 SLO 定义 —— 指标没人看等于没有指标
- **转人工没有闭环**：`human_handoff` 接不上真实工单系统
- **部署形态单薄**：Docker 未验证、无 K8s/灰度/多区域、无真实压测与容量模型
- **密钥管理**：`ANTHROPIC_API_KEY` 走环境变量，无 vault 轮转

## 四、一句话判断

**技术深度与工程完备度到位，但"多租户"目前是个假设不是保证。**
P0 补完（尤其把 `tenant_id` 从请求体挪到凭证），这东西才是一个能对外承诺的服务；
不补，它是一个架构漂亮但不能碰真实流量的作品。
