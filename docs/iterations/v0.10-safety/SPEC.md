# v0.10 · 文本安全检测（Safety）

> 起点 `97b877b`（v0.9）｜ 后继 v0.11 计费与配额
> **还 v0.4 欠的账**：流式绕过了输出脱敏。

---

## 一、迭代目的

当前安全能力是 v0.2 接线时通电的两条正则过滤器，有三个硬缺陷：

1. **🔴 流式绕过脱敏**（v0.4 遗留的已知问题）
   `delta` 是模型原始输出，而 `afterTurn` 的脱敏发生在收口阶段 ——
   **未脱敏的手机号已经打到用户屏幕上了**。v0.4 用「诚实纠正」兜住
   （改写过就告知并给准据版本），但那是补救不是修复。

2. **无分级** —— 所有命中都是同一种处理：输入命中就整轮拦截，输出命中就脱敏。
   现实里「提示词注入」和「客户自己说了句脏话」不该是同一种处置。

3. **无审计** —— 拦截了什么、脱敏了什么，没有任何留痕。
   出了纠纷无法复盘，也无法度量误杀率。

## 二、核心设计

### ⚙️ 设计① 流式感知的安全管道（滞后窗口）

问题的本质：**过滤需要看到完整文本才能判断，而流式的意义就是不等完整文本。**
敏感模式还可能跨块 —— `1381` / `2345678` 分两块到达，逐块看都不是手机号。

解法是**滞后窗口**：始终压住最后 N 个字符不发，N ≥ 最长敏感模式的长度。

```
模型输出:  请联系 138 1234 5678 处理
到达块:    [请联系 138][1234 5678][ 处理]

缓冲区演进（lag=24）:
  feed("请联系 138")      → 缓冲不足 lag，一个字不放
  feed("1234 5678")       → 仍不足，不放
  feed(" 处理")           → 仍不足，不放
  flush()                 → 扫全量 → 命中手机号 → 脱敏后一次性放出
```

**代价是首字延迟增加**（要攒够 lag 才开始吐字）。这是真实的权衡，不是免费的：
- v0.4 拿到的 27.6× 首块延迟改善，会被这个滞后窗口吃掉一部分
- 因此**滞后窗口按安全级别可配**：低敏感场景可以关掉（lag=0，退回 v0.4 行为）

### ⚙️ 设计② 四级处置

| 级别 | 处置 | 适用 |
|---|---|---|
| `allow` | 放行 | 未命中 |
| `mask` | 脱敏后继续 | 输出里的手机号/身份证/密钥 —— 丢整轮回答是可用性事故 |
| `block` | 拦截整轮 | 提示词注入、越权指令 —— 不该消耗任何 token |
| `handoff` | 转人工 | 高危但不宜自动拒绝的（人身威胁、法律纠纷） |

**`handoff` 不直接回复用户**，而是注入 `systemAppends` 让模型带着「这事该转人工」自己组织语言 ——
与 v0.8 澄清的处理方式一致。

### ⚙️ 设计③ 每一次非 `allow` 都留痕

审计条目落 session（`safety_audit` metadata），含：规则 id、级别、命中位置、处置动作。
不落原始命中内容（那本身就是敏感数据），只落**类别与位置**。

这是 v0.14 度量误杀率的数据来源 —— 没有留痕就无法回答「我们拦了多少、错拦了多少」。

### ❌ 本版不做

| 事项 | 留给 | 理由 |
|---|---|---|
| 模型侧内容审核（调审核 API） | 不做 | 正则 + 分级已覆盖电商客服的主要风险；引入外部审核 API 是另一个依赖 |
| 误杀率评测 | v0.14 | 本版负责产生审计数据，度量在评测版 |
| 按租户配置不同规则集 | v0.11 | 与租户模型一起做 |
| 工具参数的安全检查 | v0.12 | 与业务流状态机一起 |

## 五、风险预判

| 风险 | 影响 | 缓解 |
|---|---|---|
| 滞后窗口吃掉 v0.4 的首块延迟收益 | 体验倒退 | 明确写进 REPORT 并给实测数字；`safetyLag` 可配，低敏感场景可关 |
| 正则误杀正常内容（如订单号被当成身份证） | 可用性事故 | 规则加边界约束；审计留痕让误杀可被发现（v0.14 度量） |
| 替换 input-filter / output-filter 是破坏性变更 | 既有 14 条中间件用例 | 保留旧中间件与其测试，新管道并存；`buildDefaultPipeline` 切换到新的 |
| 审计写入失败拖垮对话 | 单点故障 | 审计写入失败只记警告，不阻断（与 v0.7 压缩失败同一原则） |
| 跨块检测有边界 bug，反而漏检 | 安全事故 | 用例专门构造多种切分方式（逐字符、随机切分）验证 |
