# v0.13 迭代报告 · 电商场景 II（结构化返回协议）

> 起点 `041ff25`（v0.12）｜ 用例 **496 → 548**（+52）｜ `npm run verify` exit 0
> **本版让「对外提供标准的服务」这句话第一次成立。**

---

## 一、修之前：交付的一直是个聊天接口

用户对这个项目的要求是**「能够对外提供标准的服务，而不是终端输入内容」**。
v0.6 做了 HTTP + SSE，看起来达成了。把接口摊开看：

```
SSE tool_end       → { tool, duration_ms, is_error }
POST /v1/chat/sync → { session_id, reply, usage }
```

**全是文本和元信息，没有一个字段是业务数据。**

而工具明明算出来了：`product_search` 的 metadata 里有 productId、价格、库存、评分。
这些数据被完整写进了 session，**然后在到达调用方之前被丢掉**。

接入方想在 App 里渲染一张商品卡，只能去解析模型生成的中文散文 ——
从「无线蓝牙耳机Pro，售价 299 元」里正则抠价格。模型换个说法
（「售价￥299」「299元起」「两百九十九」），解析就崩了。

> 「标准的服务」的判据不是「有没有 HTTP 接口」，
> 而是**调用方能不能不依赖自然语言解析就把功能用起来**。
> 按这个判据，前十二版交付的一直是个聊天接口。

## 二、核心设计的实际结果

### ⚙️ 设计① artifact 不经过模型

这是整个协议的立命之本，也是唯一值得写进验收的判据：

```ts
it('🔴 模型换个说法，artifact 一个字节都不变', async () => {
  provider.replyText = '为您找到以下商品';
  const a = await chat('有什么电子产品');

  provider.replyText = '亲，这几款都不错哦～售价￥两百九十九起';
  const b = await chat('有什么电子产品');

  expect(a.reply).not.toBe(b.reply);              // 文案确实变了
  expect(b.artifacts[0].data).toEqual(a.artifacts[0].data);  // 数据没变
});
```

工具产出**两份东西给两个受众**：`content` 给模型组织语言，`artifact` 给调用方渲染界面。
两者同源（由同一份计算结果分别渲染），但走不同的通道 —— artifact 从工具直接流到
SSE 与响应体，中间不被复述、不被改写。

### ⚙️ 设计② 截断必须自报

```ts
{ products: [...20 条], total: 137, truncated: true }
```

不置 `truncated` 的话，调用方会把「前 20 条」当成「全部」——
在比价场景里这直接导致错误结论。条数封顶 20 是因为 SSE 帧不可分割，
撑爆就是整条流中断。

### ⚙️ 设计③ 租户只能加严，不能放宽

```ts
it('🔴 同 id 的租户规则被忽略而不是覆盖（覆盖等价于允许放宽）', () => {
  const sneaky = { id: INPUT_RULES[0].id, action: 'mask', ... }; // 把 block 降级
  const merged = resolveSafetyRules(INPUT_RULES, [sneaky]);
  expect(merged.find(r => r.id === INPUT_RULES[0].id)).toBe(INPUT_RULES[0]);
});
```

如果允许「替换」，一个租户的配置失误就能把全局的提示词注入防护整个关掉，
**而那种事故不会有任何报错，只会在被攻击之后才被发现**。
所以类型上只提供追加接口，同 id 忽略而非覆盖。

安全规则也**刻意不通过 HTTP 配置** —— 传正则再服务端 `new RegExp` 等于开一个
ReDoS 入口。规则变更走部署，不走运行时 API。

## 三、过程中发现的问题

### 🟡 一个「先截断再排序」的陷阱

比价功能最初写成先 `slice` 再 `sort` —— 那样「最便宜的」变成「前 5 条里最便宜的」，
**给出错误答案却不报任何错**。用例专门钉住了这一点：

```ts
// 全量里最便宜的那件必须在结果里 —— 先截断再排序的话它会丢
expect(prices[0]).toBe(cheapest);
```

### 🟡 正则不能直接进 JSONB

租户的自定义安全规则要存库。`JSON.stringify(/敏感词\d+/)` 得到的是 **`{}`** ——
规则会静默变成空对象，读回来后所有租户规则一条都不生效，**且毫无报错**。
改为存 `{source, flags}`，读时重建，并写了往返用例。

### 🟢 一条断言的自我修正

`product-search.test.ts` 里有条老用例数 `---` 分隔符的个数来判断「最多 5 条」。
本版给结果加了一行「（共 6 件匹配，以上为前 5 件）」，它就红了 —— **行为一个字没变**。

改成断言 artifact 结构。这条改动本身就是本版主张的缩影：
**正确性判据不该建立在自然语言的排版上。**
