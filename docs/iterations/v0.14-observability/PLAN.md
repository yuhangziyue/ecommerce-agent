## 关键决策

**判定逻辑必须单独测。** 一个「永远返回 passed」的评测器会让所有回归门形同虚设，
而那种 bug 只有直接测 `judgeCase` 才抓得住 —— 跑一遍评测全绿是看不出来的。

**回归门要真的验证会红。** 三个维度各自人为制造一次回归，确认退出码是 1。
门不验证就等于没有门。

**不引入 OTel。** 要的是三种指标，OTel 给的是完整 trace 生态 ——
用不上的部分远多于用得上的，且 v0.15 拆服务时依赖越少越好。

## 风险处置

| 风险 | 处置 |
|---|---|
| 标签基数爆炸 | 白名单校验，未声明的标签直接抛错；用例断言指标里没有 sessionId |
| 分位数算错 | 已知分布验算；桶边界升序在装配时就校验 |
| 评测虚假安全感 | 在 SPEC / 代码注释 / 脚本输出三处都写明「评的是编排层不是模型质量」 |
| 门太严被绕过 | 阈值留余量（质量 -2% / 成本 +10% / 延迟 +50%），基线可显式更新 |
