## 关键决策

**默认值站在损失最小的一侧。** `withRetry` 的 `isRetryable` 缺省是「都不重试」，
不是「都重试」—— 重试一个可能已生效的写操作就是重复退款。

**高风险工具永不重试。** 一次超时最可能是**响应丢了而请求已经执行完了**。
宁可让客户重来一次，也不能扣两次钱。这条要有用例钉死并做断电验证。

**取消不是错误。** 把用户关页面统计成系统错误，会让错误率变成噪声，
真故障反而被淹没。

**draining ≠ 停机。** 「不接新活」和「立刻停机」差着所有在途请求的成败。
置 draining 后还要等一会儿再 close，给负载均衡的健康检查周期留时间。

## 风险处置

| 风险 | 处置 |
|---|---|
| 取消传播碰主路径 | signal 可选；不传时 617 条用例必须一条不红 |
| 重试放大故障 | 只重试瞬时错误 + 指数退避 + 次数封顶 + 熔断兜底 |
| 重复退款 | 高风险不重试，断电验证 |
| Docker 未验证 | 文件里、README 里、REPORT 里三处都标注 |
