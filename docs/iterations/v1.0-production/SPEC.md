## 二、核心设计

### ⚙️ 设计① 取消传播（还 v0.6 的账）

客户端断开后，Loop 还在跑 —— 这不是浪费 CPU，是**在给一个已经没人看的回答付钱**。

```
request.raw.on('close') → AbortController.abort()
                              ↓
        ┌─────────────────────┴──────────────────────┐
    模型调用（signal 传给 SDK）            工具执行（ToolContext.signal）
                              ↓
                    Loop 在下一个检查点退出
```

**取消不是错误**：中断的轮次记为 `outcome=cancelled`，不是 `error` ——
把用户主动关页面记成系统错误，会让错误率指标变成噪声。

### ⚙️ 设计② 熔断 + 重试（还 v0.15 的账）

v0.15 只保证了错误语义正确，没有韧性。补上两件事：

```
重试：仅对**幂等且瞬时**的失败（连接失败/超时/5xx），指数退避，最多 2 次
      ⚠️ 高风险工具（退款/开票）**永不重试** —— 重试一个可能已经生效的写操作
         就是重复退款

熔断：连续 N 次失败 → 打开，快速失败不再撞墙
      半开：冷却后放一个探针请求过去，成功则关闭
```

熔断器的价值不在「保护下游」，在**保护自己**：下游挂了的时候，
不熔断意味着每个请求都要等满超时时间，线程/事件循环被拖死，
最后是**整个服务一起挂**，而不只是那一个功能不可用。

### ⚙️ 设计③ 优雅退出

```
SIGTERM → 停止接受新请求 → 等在途请求完成（有上限）→ 关闭 DB/Redis → 退出
                              ↑
                        超过上限就强制退出，不能无限等
```

配合 `/healthz` 的 draining 状态：收到信号后健康检查立刻转为不健康，
让负载均衡在**旧实例还能服务在途请求的同时**停止给它派新活。

## 三、边界

### ✅ 本版做

| # | 事项 | 类型 |
|---|---|---|
| 1 | `AbortSignal` 贯通 Loop / 工具 / 模型调用 | 设计① |
| 2 | 客户端断开 → 中断本轮，记 `cancelled` | 设计① |
| 3 | `CircuitBreaker`（关闭/打开/半开） | 设计② |
| 4 | 带退避的重试，**高风险工具不重试** | 设计② |
| 5 | `RemoteToolGateway` 接入熔断与重试 | 设计② |
| 6 | 优雅退出 + draining 健康检查 | 设计③ |
| 7 | Dockerfile + compose（两个服务 + PG + Redis） | 部署 |
| 8 | **README 重写**（还 D-1） | 文档 |
| 9 | 架构总览与最终验收报告 | 文档 |

### ❌ 本版不做

| 事项 | 理由 |
|---|---|
| K8s manifests / Helm | compose 已足够表达拓扑；K8s 是各家自己的事 |
| 多区域 / 灾备 | 超出单仓库范畴 |
| 真实压测数字 | 本机无法产生可信的生产压测结论，给了也是误导 |
| 真实 Docker 构建验证 | **本机没有 Docker**，产物给出但明确标注未验证 |

## 五、风险预判

| 风险 | 影响 | 缓解 |
|---|---|---|
| 取消传播碰 Loop 主路径 | 回归面大 | signal 可选；不传时行为与 v0.15 完全一致 |
| 重试放大故障 | 下游被打垮 | 只重试瞬时错误、指数退避、次数封顶、熔断兜底 |
| **重试写操作 → 重复退款** | 资损 | 高风险工具**永不重试**，用例钉死 |
| 熔断误判导致可用功能不可用 | 可用性 | 阈值可配、半开探针快速恢复 |
| Docker 产物未经验证 | 部署踩坑 | **明确标注未验证**，不假装它跑过 |
